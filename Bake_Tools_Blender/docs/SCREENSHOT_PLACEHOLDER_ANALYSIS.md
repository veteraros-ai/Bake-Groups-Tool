# Анализ снимка-подложки Qt-менеджера

## Цель

Во время временного скрытия owned PySide6 HWND оставить в Blender визуальный отпечаток менеджера, чтобы область не выглядела пустой. Подложка должна быть неинтерактивной и не сохраняться в `.blend`.

## Что технически возможно

1. Qt может снять содержимое `BakeToolsWindow` через `QWidget.render()` или `grab()` в `QImage/QPixmap` без системного снимка рабочего стола.
2. Пиксели можно передать во временный `bpy.types.Image`, получить `GPUTexture` и нарисовать через `SpaceView3D.draw_handler_add(..., 'WINDOW', 'POST_PIXEL')` и `gpu_extras.presets.draw_texture_2d()`.
3. Снимок нужно обновлять только при изменении UI, размера, языка или DPI. Загрузка изображения в GPU на каждом 100-мс pump недопустима.

## Главные ограничения

- Draw handler региона `WINDOW` обрезается рабочей областью View3D. Текущий менеджер находится над регионом `UI` (Sidebar), а публичного Python draw handler для произвольной отрисовки поверх всего `UI` региона нет. Поэтому точная подложка в том же месте через поддерживаемый API не гарантируется.
- `UILayout` умеет стандартные preview/image templates и большие icons, но не является canvas: нельзя точно воспроизвести полноразмерный скрин, его размеры, прокрутку и позицию под существующими RNA-кнопками.
- Снимок выглядит как настоящий интерфейс, но не принимает события. Без затемнения или подписи пользователь будет нажимать на неработающие кнопки.
- Qt использует logical pixels и `devicePixelRatio`, Blender GPU — координаты региона и framebuffer. При переносе между мониторами нужны пересчёт DPR, повторный capture и пересоздание texture; иначе появятся размытость и смещение.
- Нужно корректно обработать premultiplied alpha и преобразование sRGB/scene-linear, иначе цвета кнопок изменятся.
- Blender popup может быть отдельным GHOST HWND либо `TEMPORARY` region внутри главного окна. Порядок композиции такого popup и `POST_PIXEL` подложки различается; подложка способна снова визуально перекрыть именно тот popup, ради которого Qt-окно было скрыто.
- Draw handler и GPU resource должны удаляться при Close, unregister, смене файла, уничтожении area и Workspace. Утёкший callback со старым RNA/GPU объектом — потенциальный источник падения Blender.
- Снимок лога может содержать локальные пути. Временный image нельзя pack/save в `.blend` или писать на диск.

## Варианты

### Полная подложка в Sidebar

Не рекомендуется. Публичный Blender API не даёт надёжного pixel-perfect canvas в регионе `UI`; обход потребует внутренних GHOST/Win32 решений и вернёт риски z-order и зависаний.

### Viewport HUD рядом с Sidebar

Технически реализуем через `POST_PIXEL`, но занимает рабочую область, меняет положение интерфейса и может закрывать модель/навигацию. Для постоянного использования хуже текущего overlay.

### Короткий freeze-frame только во время popup suppression

Допустим как отдельный эксперимент: один capture при начале suppression, временная GPU texture, фильтр по host Workspace и host area, затемнение и подпись `Bake Tools temporarily inactive`, немедленное удаление после восстановления. Сначала обязательны тесты popup draw order, двух мониторов, 100/125/150% DPI и повторного открытия файла.

## Решение

В 1.2.0 снимок-подложка не включён. Для смены Workspace визуальное исчезновение является правильным результатом и снимок там тоже должен отсутствовать. Для Blender popup лучше сокращать длительность native suppression и улучшать transient z-order; это сохраняет настоящий интерактивный интерфейс и не создаёт ложную картинку кнопок.
